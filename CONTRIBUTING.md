# Contributing

## Welcome

Welcome dudes of all shapes, sizes and persuasions!

This is my open invitation for anyone who wants to help out on this project. I want this to be a safe and fun space for people to collaborate on a shared objective.

I started using Grocy to help reduce waste and help with efficiency. Taking inventory with the app is painful though. The app's user experience (UX) is dated, clunky and does not promote efficient workflows. You can't do anything in batches; there is no bulk editing; the UI is confusing and unintuitive, to name but a few shortcomings. However, it is still a powerful, intelligently designed application with a solid data model and most of the core functionality is very well designed and implemented. I think Grocy deserves a refresh and modernization effort and that's what this project is about.

I am just one dev-dude, trying to give back to the community that has served me so well. I will do my best to be a responsible and responsive maintainer. Understand though, that this is very much a side project. Almost all of the content in this repo is AI generated, save this section. I am doing my very best to keep my agents on a short leash and I ask the same of you.

I use Matt Pocock's skills and I suggest you do the same when working on this project with coding agents. https://github.com/mattpocock/skills Please make sure your agents use ASD-STE100 language within this repo, as it helps avoid that typical, AI techno-babble, word salad that no one enjoys reading!

Above all, please be respectful and try to have fun. Anyone who is being un-dude, will not be tolerated.

## Ways to help

You do not have to write code to help.

- Ask a question in
  [Discussions](https://github.com/the-dev-abides/grocy-next/discussions).
- Report a bug with the
  [bug template](https://github.com/the-dev-abides/grocy-next/issues/new/choose).
- Request a feature with the feature template.
- Test a build against your own Grocy and report what you find.
- Fix or improve the documentation.
- Write code. Issues with the
  [good first issue](https://github.com/the-dev-abides/grocy-next/labels/good%20first%20issue)
  label are a good place to start.

## Issues

A good bug report says what happened, what you expected, and the steps to
repeat it. The template asks for these. The maintainer reads and answers every
issue.

Before you start a large change, open an issue and describe it. This saves
your time if the change does not fit the plan.

## Pull requests

The maintainer looks for these things in a pull request:

- Intent. The description says the problem and the change. It links the
  issue.
- Tests that cover the change.
- A passing run of the repo checks.
- A record of each decision that another option could replace.
- A note in the description when an agent wrote part of the code.

Keep a pull request small. One pull request makes one change. The pull
request template has a checklist for these points.

## Agent-assisted pull requests

Pull requests written with an AI agent are allowed. The human author:

- Says so in the pull request description.
- Has read every line of the change.
- Has run the tests on their machine.
- Is responsible for the change.

## Language

The maintainer writes the documentation in ASD-STE100 Simplified Technical
English (STE). A human contributor does not have to write STE. Plain English
is fine. Text that an AI agent writes must be STE. The Welcome section above
says why.
